## 1. Обязательные правила работы

Эти четыре правила не обсуждаются. Они дороже любой отдельной функции, потому что именно их
нарушение съедает недели.

### 1.1. Архетип Бьёрна Страуструпа

Автор C++ сформулировал принципы, которым здесь надо следовать буквально:

- **Абстракция не должна стоить дороже, чем ручная работа.** Обёртка, которая «на всякий случай»
  добавляет слой, но не убирает ни одной ошибки, — это не абстракция, а налог.
- **Ошибку должен ловить тип, а не тест и не человек.** Если статус публикации может быть только
  одним из пяти значений — это литеральный тип, а не строка. Если функция не работает без
  подключённого аккаунта — аккаунт приходит аргументом, а не достаётся из глобального состояния.
  `mypy --strict` и Pydantic v2 — не украшение, а способ переложить проверки на компилятор.
- **Не платишь за то, чем не пользуешься.** Не тащи Redis, Celery, Kubernetes и микросервисы в
  продукт, который обслуживает команду из нескольких человек.
- **Цена решения называется вслух.** У каждого выбора есть обратная сторона. Выбрал — напиши
  рядом, чем платишь. Молчаливый компромисс через месяц выглядит как чужая глупость.

Практически: каждое непростое решение сопровождается комментарием в коде, который объясняет
**почему так, а не иначе**, и **что сломается**, если сделать «очевидным» способом. Примеры такого
комментария есть в разделе 9 — пиши так же.

### 1.2. Альманах граблей — обязателен

Заведи `docs/ALMANAC.md` **в первый день, до первой строчки кода**, и веди его всё время.

Структура записи:

```markdown
### 5.7. Выпадашка не открывается на планшете

**Симптом:** тап по селектору ничего не делает, в браузере на десктопе работает.
**Причина:** panel открывается на `pointerdown`, а хвост того же тапа прилетает уже
в открытую панель и немедленно её закрывает.
**Решение:** открывать на `pointerup` + окно 400 мс, в которое панель не принимает выбор.
**Профилактика:** тест бьёт настоящей цепочкой touch-событий, а не синтетическим кликом.
**Ключевые слова:** тап, планшет, выпадашка, схлопывается, мобильный
```

**Протокол (соблюдать буквально):**

1. Упал тест или непонятная ошибка → **сперва grep по альманаху дословным текстом ошибки**,
   потом уже исследование. `grep -n -i -A15 "FloodWaitError" docs/ALMANAC.md`
2. Запись есть → берёшь готовое решение. Цена уже уплачена однажды.
3. Записи нет → чинишь → **сразу пишешь запись, пока причина в голове**. Через день от неё
   останется только симптом. Проблема, отнявшая больше 15 минут, записывается в тот же день.
4. Грабли повторились дважды → пишешь **исполняемый тест**, а не третью запись. Знание без
   автопроверки не срабатывает.

Заголовок записи — **по симптому**, а не по причине: искать будут по симптому. Обязательна строка
`Ключевые слова:` с человеческими синонимами.

Стартовые записи, которые нужно внести сразу, — в разделе 15. Они уже оплачены чужой кровью.

### 1.3. Доказательство от обратного

**Тест, который не краснеет от порчи кода, — это не тест.**

После каждого нового теста: сломай намеренно ту строку продукта, которую он сторожит, убедись,
что тест **упал**, верни как было. Не проверил — считай, что теста нет.

Это не паранойя. В системе-предшественнике так были найдены проверки, зелёные на полностью
сломанном коде: тест сверял собственную копию правила вместо самого правила; тест начинал с
пустого состояния, где сломанный код согласован сам с собой; тест искал элемент по классу,
который порча удаляет, — и «элемент не найден» удовлетворяло условию.

### 1.4. Порядок сдачи любой правки

```
mypy --strict → ruff → pytest (юниты + тесты на живой БД) → Playwright → деплой → живая проверка на проде → уборка
```

- **Живая проверка обязательна.** Код возврата `0` у деплоя не значит, что работает. Открой,
  нажми, посмотри глазами, сверь цифру запросом к базе.
- **Тестовые данные прода чистятся в тот же заход**, и не «я удалил», а сверкой запросом: было
  столько, стало ноль.
- **Перед любой правкой — бэкап.** Раздел 13.
- **Перед началом задачи изложи заказчику своё понимание и получи подтверждение.** Домысленная
  функция хуже несделанной: она съедает время и создаёт то, чего не просили.

## A. Проверочный список по этому коду

Выведен из разбора `smmparsers/` — это применение раздела 1.1 к найденным здесь дефектам.
Каждый пункт закрывает конкретное место, а не общее пожелание.

1. **Комментарий, расходящийся с кодом, — дефект.** Прецеденты в этом репозитории:
   `history()` обещает не читать строки и читает их целиком; обработчик `FloodWaitError`
   обещает, что просмотренное не потеряно, и теряет его. Текст в интерфейсе — тоже контракт:
   подпись «файл собран целиком» стоит над кнопкой, отдающей урезанный файл.
2. **Инвариант — конструкцией, а не намерением.** Разделение данных между сотрудниками
   объявлено в трёх комментариях и сломано глобальным `_job` и общим каталогом результатов.
3. **Ключ должен быть устойчивым.** `id(client)` как ключ кеша — адрес в памяти,
   переиспользуемый после сборки мусора.
4. **Владение ресурсом ограничено по времени.** Словари `_clients`, `_dialogs`, `_login_phone`,
   `_fails` и каталог сессий растут без единой точки освобождения.
5. **Ошибка не превращается в `None` или пустую строку.** Молча неверный ответ хуже отказа;
   для конвейера сбора это означает: невозможность разобрать страницу останавливает работу,
   а не досчитывает нулями.
6. **Проверяем, а не чиним.** Некорректный идентификатор отвергается (`fullmatch` → 404),
   а не приводится к правдоподобному виду вырезанием символов.
7. **Единственный источник истины.** Набор полей выгрузки задан в трёх местах; расхождение
   ничем не ловится.
8. **Модель угроз проверяется по факту.** Сессии шифруются, а персональные данные участников
   лежат рядом открытым текстом — заявленная защита не достигнута.

Полный разбор с номерами строк — в истории обсуждения; сводка дефектов не дублируется здесь,
чтобы не разойтись с кодом (см. пункт 1).

## B. Что это за продукт

**Instagram-ветка — вход в контент-движок, а не отчётность.** Цикл: сбор по кукам браузерной
сессии с двух источников (сетка аккаунта и страница публикации) → расчёт виральности →
транскрибация победителей через Whisper → классификация → синтез сценария для своих публикаций
через MCP. Парсер — интакт данных для этого цикла.

**`smmparsers/tg-parser/`** — отдельная линия, к контент-движку не относится: веб-обёртка над
Telethon, считает активность участников группы по ключевому слову за диапазон дат, отдаёт CSV.
FastAPI + Jinja2 + Docker.

**`smmparsers/instagram_parser.py`** — в репозитории лежит **ранний прототип** (2025-11-04,
на десять месяцев старше `tg-parser`): анонимный доступ без кук, без исполнения JavaScript,
без расчёта виральности, без транскрибации. Рабочая куки-версия ожидается от заказчика.
**Не принимать этот файл за описание текущей системы.**

## C. Чего сейчас нет для исполнения пункта 1.4

Названо вслух, потому что порядок сдачи из 1.4 сегодня физически неисполним:

- нет конфигурации `mypy` и ни одной аннотации под `--strict` в `instagram_parser.py`;
- нет `ruff` и его настроек;
- нет `pytest`, ни одного теста и каталога для них;
- нет Playwright и вообще браузерных проверок;
- **нет базы данных** — результаты лежат JSON-файлами, поэтому «тесты на живой БД» пока не к чему
  применить;
- нет процедуры бэкапа (раздел 13 не передан).

Порядок восстановления инструментария согласуется с заказчиком до первой правки кода:
раздел 1.4 требует прогона, которого сейчас нет.

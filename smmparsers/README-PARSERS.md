# Что в этом архиве — и что из этого работает

Собрано с боевого сервера заказчика 10.09.2026. Ничего не додумано: то, чего нет, названо
отсутствующим.

## 1. tg-parser/ — РАБОТАЕТ, крутится в проде

Веб-обёртка над Telethon: вход общим паролем, у каждого вошедшего свой Telegram, поиск в группе
по ключевому слову за период, результат — **рейтинг людей** (кто сколько раз писал), вторая
вкладка со списком сообщений, CSV, история двадцати прогонов.

Состав: `docker-compose.yml`, `Dockerfile`, `requirements.txt`, `set-password.sh`, `app/main.py`,
`app/templates/`. Секретов внутри нет — `.env` и содержимое тома исключены.

**Формат хранения — файлы, базы нет:**

| Что | Где | Как |
|---|---|---|
| Ключи приложения и сессия Telegram | `/data/sessions/<sid>.enc` | JSON, шифрован Fernet, ключ в окружении |
| Результат прогона | `/data/results/<job_id>.json` | шапка + строки для экрана |
| Выгрузка | `/data/results/<job_id>.csv` | все строки, `utf-8-sig` |

Колонки результата: `message_id, date, count, user_id, username, name, text, views, link`.
Хранятся последние 20 прогонов, старые удаляются. На экран отдаётся не больше 5000 строк, и об
усечении говорится вслух; CSV собирается целиком.

## 2. instagram_parser_original.py — УСТАРЕЛ, сегодня не работает

Тот самый файл с сервера (ноябрь 2025). По ссылке на Reels доставал автора, лайки, комментарии и
просмотры со страницы профиля, **без кук**.

Проверено живьём 10.09.2026 с серверного адреса — оба его шага мертвы:

* `instagram.com/<username>/reels/` → **302 на `/accounts/login/`**;
* страница самого рилса → 625 КБ пустой оболочки **без `og:description` и `og:url`**, ровно
  столько же на заведомо несуществующий код.

Оставлен как исходник, а не как рабочий инструмент.

## 3. instagram_parser_cookies.py — СОБРАН из работающих кусков, требует кук

Отдельного файла «версии с куками» на серверах НЕ СУЩЕСТВУЕТ — проверено полным обходом диска.
Куки живут **узлами n8n** в воркфлоу `IOkD7XFeOO44luxM` («DeOldify»): `HTTP Request3` и
`HTTP Request4` ходят на `/<username>/reels/` с заголовками `Cookie` и `X-CSRFToken`.

Этот файл — те же куски, сведённые вместе: извлечение автора четырьмя способами из исходного
парсера, разбор `og:description` из узлов `Code4`/`Code5`, запрос с куками из `HTTP Request3`.

Нужны шесть кук: `sessionid, csrftoken, ds_user_id, mid, ig_did, rur`; `csrftoken` дублируется
заголовком `X-CSRFToken`. Передаются переменной `IG_COOKIE`, в файл не зашиты.

```
export IG_COOKIE='sessionid=...; csrftoken=...; ds_user_id=...; mid=...; ig_did=...; rur=...'
python3 instagram_parser_cookies.py https://www.instagram.com/reel/XXXXXXXXX/
```

Отдаёт JSON: `shortcode, username, likes_count, comments_count, views_count, views_note`.
Пустое значение объясняет себя: протухшие куки, изменившаяся вёрстка или рилс уехал вниз по ленте.
**Проверить с живыми куками я не мог — их нужно взять из браузера.** Без кук файл честно отвечает
отказом, это проверено.

Куки — живая сессия аккаунта, его могут ограничить. Отдельный аккаунт под задачу, не рабочий.

## 4. whisper_server.py — РАБОТАЕТ, но НИ К ЧЕМУ НЕ ПОДКЛЮЧЁН

Flask + модель Whisper `small`, один маршрут `POST /transcribe`, принимает файл до 100 МБ,
возвращает расшифровку JSON-ом. Живёт на сервере под gunicorn на `0.0.0.0:5001`
(`/opt/whisper-venv`), процесс поднят.

**Ничего не хранит** — ответ отдаётся вызывающему и всё.

**Связки «Whisper + классификация» НЕТ.** Проверено поиском по всем воркфлоу: на `:5001` и
`/transcribe` не ходит ни один узел. Цепочка в «DeOldify» получает поле `transcrib` **из текста
сообщения Telegram**, то есть расшифровку туда вставляет человек руками.

И сама цепочка — не классификация, а **генерация сценариев**: GPT-4.1 по транскрипту пишет три
варианта Reels на украинском (Hook → основная часть → призыв, до 30 секунд, с режиссёрскими
ремарками), затем отдельный узел рисует коллаж из трёх сцен, результат уходит в Telegram, часть
данных пишется в Google Sheets (лист «Результаты», `appendOrUpdate`).

Сам воркфлоу **выключен**, сохранённых исполнений в базе нет.

# Часть 1. Уже наступали

## 1. Развёртывание и Docker

### 1.1. Панель не пускает по верному паролю сразу после развёртывания

**Симптом:** пароль введён правильно, вход не происходит; в логах — ошибка разбора хеша.
**Причина:** `docker compose` трактует `$` в значении внутри `env_file` как подстановку
переменной и вырезает его. Хеш вида `соль$хеш` приезжал в контейнер без разделителя.
**Решение:** разделитель в `PANEL_PASSWORD_HASH` — **двоеточие**, а не `$`
(`main.py:50`, `verify_password` делит по `":"`).
**Профилактика:** любой секрет, попадающий в `env_file`, проверяется на `$` до записи;
формат хеша — только hex и двоеточие.
**Ключевые слова:** пароль не подходит, не пускает, env_file, доллар, хеш, scrypt, разделитель

### 1.2. Приложение не может писать в `/data` после первого запуска

**Симптом:** контейнер поднялся, но любое действие падает на записи; каталог пуст.
**Причина:** Docker переносит владельца на **пустой** том. Том достаётся `root`, а процесс
работает под непривилегированным пользователем и писать не может. Наступали 20.08 на CRM.
**Решение:** каталог данных создаётся **в образе** и передаётся пользователю до `USER`:
`RUN mkdir -p /data && chown tg:tg /data` (`Dockerfile:14`).
**Профилактика:** в любом образе с непривилегированным пользователем каталог тома создаётся
и раздаётся в самом Dockerfile, а не рассчитывается на монтирование.
**Ключевые слова:** permission denied, не пишет, том, volume, root, права, docker, пустой каталог

### 1.3. 404 на форме, адрес которой заведомо верный

**Симптом:** приложение открывается под префиксом пути (например `/tg`), главная работает,
а POST на `/tg/keys` отдаёт 404.
**Причина:** Starlette при заданном `root_path` срезает префикс с пути **до** поиска маршрута.
Маршруты, у которых тот же сегмент присутствует в адресе, переставали находиться вовсе.
**Решение:** `root_path` не задаётся намеренно. Префикс нужен только для ссылок и пути cookie
и подставляется вручную через переменную `ROOT` (`main.py:403`).
**Профилактика:** при развёртывании под префиксом проверяется не только главная страница,
но и каждый POST-маршрут.
**Ключевые слова:** 404, префикс, root_path, поддиректория, nginx, маршрут не найден, Starlette

## 2. Telegram / Telethon

### 2.1. В выборку не попадает последний день диапазона

**Симптом:** заказчик просит «1–31 августа», в файле нет ни одного сообщения за 31-е.
**Причина:** `offset_date` в Telethon отдаёт сообщения строго **старше** отметки. При
`offset_date=date_to` последний день терялся молча.
**Решение:** верхняя граница берётся как начало **следующих** суток
(`end_excl = date_to + 1 день`), нижняя проверяется через `if message.date < start: break`.
Обе даты включительно (`main.py:340`).
**Профилактика:** тест на диапазон из одного дня: сообщение, отправленное в этот день,
обязано попасть в результат.
**Ключевые слова:** пропал день, последний день, диапазон, offset_date, даты, не все сообщения

### 2.2. Даты расходятся с отчётом на сутки на краях месяца

**Симптом:** число совпадений не сходится с ручным подсчётом ровно на сообщения,
отправленные поздно вечером или ночью.
**Причина:** границы считались по UTC, а человек, который пишет «1–31 августа», имеет в виду
свой календарь. Так же считают отчёты CRM.
**Решение:** границы строятся в киевской зоне и переводятся в UTC уже после
(`APP_TIMEZONE`, по умолчанию `Europe/Kyiv`, `main.py:47`).
**Профилактика:** любая дата, полученная от человека, до сравнения переводится в зону
из конфигурации; UTC — только внутреннее представление.
**Ключевые слова:** не сходится, на сутки, часовой пояс, UTC, Киев, полночь, ночные сообщения

## 4. Выгрузка и данные

### 4.1. Кириллица в CSV открывается крякозябрами

**Симптом:** файл выгружен, в Excel вместо русского текста мусор; в блокноте всё правильно.
**Причина:** Excel не определяет UTF-8 без метки порядка байтов.
**Решение:** файл пишется в `utf-8-sig` (`main.py:380`), в браузерной выгрузке BOM
добавляется в начало Blob вручную (`index.html:292`).
**Профилактика:** проверять выгрузку открытием именно в Excel, а не в редакторе.
**Ключевые слова:** крякозябры, абракадабра, Excel, кодировка, UTF-8, BOM, csv, иероглифы

# Часть 2. Найдены разбором кода

Причина подтверждена чтением исходника или запуском. В проде могли не проявиться либо
проявляться молча — это и есть их главная опасность.

## 2. Telegram / Telethon

### 2.3. Ссылка «последнее ↗» ведёт в другой чат или в никуда

**Симптом:** рейтинг верный, но ссылка на сообщение участника открывает чужой чат
либо страницу с ошибкой. Воспроизводится не на всех группах.
**Причина:** к `entity.id` применяется срезка префикса `100`, взятая из работы с
**маркированными** идентификаторами (`-100…`). Но `entity.id` в Telethon — уже голый id.
Если голый id канала сам начинается на «100», он режется:
`1001234567 → 1234567` (проверено запуском).
**Решение:** не срезать префикс у `entity.id` (`main.py:345`). Срезка уместна только там,
где идентификатор действительно маркированный, — например для значений из `iter_dialogs`.
**Профилактика:** тест на канал с голым id, начинающимся на `100`; сверка построенной
ссылки с фактическим адресом сообщения.
**Ключевые слова:** ссылка не открывается, чужой чат, t.me/c, id канала, 100, битая ссылка

### 2.4. Голосовые не попадают в выборку, счётчик молчит

**Симптом:** участник отмечался в чате, в рейтинге его нет; жалуется, что «всё отправлял».
**Причина:** `if not message.text` отбрасывает сообщение **до** проверки ключевого слова
(`main.py:354`). У голосовых и «кружочков» подписи в Telegram не бывает в принципе,
поэтому их текст пуст и они невидимы для поиска. Фото и видео с подписью ищутся нормально.
**Решение:** пока не сделано. Требуется источник текста для голосовых — расшифровка Telegram
для Premium-аккаунта либо собственная транскрибация.
**Профилактика:** при отсутствии расшифровки — считать и показывать количество пропущенных
сообщений без текста, чтобы «ноль совпадений» не выглядел как достоверный ноль.
**Ключевые слова:** голосовое, кружочек, нет в рейтинге, не посчитало, войс, аудио, пропустил

### 2.5. Сотрудник видит чужие выгрузки и чужие чаты

**Симптом:** вошёл под общим паролем — на экране история поисков коллеги и тексты сообщений
из чужого клиентского чата. В выпадашке групп — чужие чаты.
**Причина:** два места. Первое: `_job` — один глобальный объект, каталог `RESULTS` не разделён
по пользователю, `/history` и `/results` отдают всё подряд (`main.py:199`, `587`, `605`).
Второе: кеш списка диалогов ключуется `str(id(client))` — адресом объекта в памяти
(`main.py:271`); после освобождения клиента адрес переиспользуется другим, и кеш живёт 5 минут.
**Решение:** результаты складывать в `RESULTS / sid`, `_job` держать словарём по `sid`,
кеш диалогов ключевать `sid`.
**Профилактика:** тест на двух одновременных сессиях: то, что видит один, не должно появляться
у другого ни в одном ответе.
**Ключевые слова:** чужие данные, чужой чат, утечка, история поисков, сессия, изоляция, sid

### 2.6. После долгой паузы Telegram теряется вся проделанная работа

**Симптом:** длинный прогон шёл минуты, упал с сообщением про ожидание; повторный запуск
начинает с нуля. Сообщение при этом уверяет, что «просмотренное не потеряно».
**Причина:** накопленные строки — локальная переменная `run_job`; исключение `FloodWaitError`
выходит из цикла, переменная уничтожается, файл не пишется (`main.py:390`). Текст сообщения
не соответствует поведению.
**Решение:** писать строки в CSV потоком по мере нахождения, тогда частичный результат
переживает обрыв; либо переписать сообщение, если частичный файл не нужен.
**Профилактика:** любое сообщение об ошибке, утверждающее что-то о сохранности данных,
проверяется тестом на эту сохранность.
**Ключевые слова:** FloodWaitError, подождите, флуд, пауза, потерялось, начинает заново, обрыв

## 3. Instagram

### 3.1. Парсер возвращает нули вместо ошибки — кука мертва

**Симптом:** сбор идёт, ошибок нет, но лайки, комментарии и просмотры приходят пустыми
у всех публикаций подряд.
**Причина:** при потере доступа Instagram отдаёт **стену логина с кодом 200**.
`raise_for_status()` её пропускает как успешный ответ, разбор ничего не находит и кладёт
`None` в поля вместо отказа (`instagram_parser.py:27`, `:127`).
**Решение:** явно распознавать страницу логина и **останавливать конвейер** с внятной причиной.
Невозможность разобрать страницу — отказ, а не пустое значение.
**Профилактика:** тест на сохранённой HTML-странице логина: разборщик обязан упасть,
а не вернуть нули.
**Ключевые слова:** нули, пусто, None, кука протухла, разлогинило, стена логина, 200, лайки нет

### 3.2. Статистика приписана не тому аккаунту

**Симптом:** цифры собрались, но принадлежат чужой публикации; при повторном запуске
результат может отличаться.
**Причина:** имя аккаунта ищется рекурсивным обходом встроенного JSON и возвращается
**первое попавшееся** поле `username` в порядке обхода словаря (`instagram_parser.py:45`).
В этом JSON десятки имён: зритель, рекомендованные аккаунты, авторы комментариев.
**Решение:** брать автора по известному пути в структуре ответа, а не поиском по всему дереву;
при неоднозначности — отказ.
**Профилактика:** тест на сохранённой странице, где заведомо есть посторонние `username`;
проверяется совпадение с ожидаемым автором.
**Ключевые слова:** не тот аккаунт, чужая статистика, username, нестабильно, разные результаты

## 4. Выгрузка и данные

### 4.1. Кнопка «Скачать CSV» отдаёт неполный файл под подписью «собран целиком»

**Симптом:** на экране написано «первые 5 000 из N, остальное есть в файле, который собран
целиком», а в скачанном файле — те же 5 000.
**Причина:** кнопка вызывает сборку файла **в браузере** из строк, уже усечённых для экрана
(`index.html:284`). Серверный маршрут `/download/{job_id}`, отдающий полный файл, не вызывается
ниоткуда — проверено поиском по всем шаблонам.
**Решение:** увести кнопку на `/download/{job_id}`.
**Профилактика:** тест на выборке больше `SCREEN_LIMIT`: число строк в скачанном файле
обязано совпадать с числом найденных, а не с числом показанных.
**Ключевые слова:** неполный файл, урезано, 5000, скачать csv, не все строки, download

### 4.2. Ноль просмотров неотличим от «неизвестно»

**Симптом:** в колонке просмотров пусто; непонятно, ноль это или не считалось.
**Причина:** `message.views or ""` — при `views == 0` в числовую колонку попадает пустая строка
(`main.py:374`).
**Решение:** проверять `is not None`, а не истинность значения.
**Профилактика:** правило для всех числовых полей выгрузки: `0` и «нет данных» различимы.
**Ключевые слова:** пустая колонка, просмотры, ноль, views, нет данных, csv

# План переноса на ВПС

> **Статус: предложен, отмашки заказчика НЕТ.** Ни один шаг не выполняется до подтверждения.
> Документ лежит в репозитории, чтобы сессия, запущенная на самом сервере, подхватила
> контекст: переписка туда не переносится, репозиторий переносится.

## Задача

Собрать на `myparser.ungurianbody.com` (37.60.234.112) самостоятельный стек **без n8n**:
сбор Instagram по кукам → виральность → транскрибация → классификация → хранение корпуса →
витрина MCP для написания сценариев. `tg-parser` остаётся и работает.

## Порядок шагов

Каждый шаг проверяется до перехода к следующему.

**0. Снимок и бэкап.** `scripts/audit.sh` — читает и ничего не меняет. Бэкап по разделу 13
инструкции (не передан) либо по согласованной процедуре. **Без отката на прод не идём.**

**1. Периметр и доступы.** SSH только по ключу, `PermitRootLogin prohibit-password`, fail2ban,
ufw (наружу 22/80/443). Whisper с `0.0.0.0:5001` уводится на `127.0.0.1`, наружу — через nginx.
Единственный шаг, который чинит живую дыру сегодня.
*Осторожно:* правила экрана меняются так, чтобы не отрезать себе доступ — разрешающее правило
до включения, проверка входа из второго окна.

**2. Инструментарий под правило 1.4.** `mypy --strict`, `ruff`, `pytest`, Playwright, каталог
фикстур. До него ни одна правка не сдаётся по правилам: прогона сейчас не существует.
Первые фикстуры: страница рилса под живыми куками и гостевая оболочка — без них куки-парсер
не проверяем никак.

**3. Четыре правки `tg-parser`.** Первой — разделение результатов по сотрудникам (`almanac 2.5`):
сегодня вошедший видит выгрузки коллеги и тексты из чужого клиентского чата, это работает в проде.
Затем ключ кеша диалогов, кнопка CSV на серверный файл (`almanac 4.2`), срезка `100` в
ссылках (`almanac 2.3`).

**4. Хранилище.** SQLite в режиме WAL. Таблицы: аккаунты, публикации, замеры метрик, транскрипты,
классификация, очередь заданий.
*Цена вслух:* один писатель, по сети не ходит. Для команды в несколько человек это плюс —
бэкап равен копированию файла. Переезд на Postgres — когда упрёмся в блокировки, а не раньше.

**5. Сбор Instagram как сервис.** Куки-парсер из разового скрипта — в воркера очереди: контроль
темпа, проверка живости кук, отказ вместо нулей. Закрыть `almanac 3.2` (запасной способ маскирует
протухшие куки) и `almanac 3.3` (потеря лайков на крупных числах и локали). Виральность считается
от медианы просмотров аккаунта по той же странице сетки, которая и так грузится.

**6. Whisper.** Закрыть `almanac 6.1`–`6.5`: порт наружу, утечка `/tmp`, 413 в HTML, копия модели
на воркер, `word_timestamps=True` и явный язык. Подключить к конвейеру — расшифровка ложится
в базу, а не отдаётся в никуда.

**7. Классификация.** Поля: хук и что прозвучало в первые три секунды, структура, хронометраж,
темп речи, призыв, формат подачи, язык. **Требует решения заказчика:** считает модель на сервере
или Claude через MCP.

**8. Витрина MCP.** Только чтение: топ по виральности, транскрипт и разбор публикации, база
аккаунта. Сбор в витрину **не заводим** — он медленный и лимитируемый, ему место в фоновом
конвейере.
*Цена вслух:* оркестрация — воркер по таблице заданий плюс таймеры systemd. Ни Celery, ни Redis:
очередей мало, машина одна. Расплата — нет распределённых повторов и панели, как в n8n.

## Чего не делаем без отдельного решения

- **Не гасим n8n.** Куки живут в его узлах (воркфлоу `IOkD7XFeOO44luxM`) — это единственный
  работающий рецепт. Извлечь до того, как что-то выключать.
- Не трогаем то, что не названо: другие сайты, почту, прочие службы.
- Не переносим и не удаляем том `tg-parser` — там живые сессии Telegram сотрудников.
- Не заводим платных подписок и не подключаем внешние API без слова заказчика.
